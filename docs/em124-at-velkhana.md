## 2. AI 结构

历战王与普通冰呪龙**共用同一套 THK**。主控 `node_000` 用 `self.current_quest().is_rank(rank.AT)` 分流，Global 里大量节点也按这个条件选择历战王版本的招式（`ex_` 前缀）。以下只讨论历战王路径（可达 212 个节点）。

```
node_000 ── 历战王 → node_002
  node_002  R8 清零 → G432 大型怪同场 → G181 烟雾弹 → node_003 选目标 → node_004
  node_004
   ├─ G141  额外落冰（R7=2 必落；冰2 2200~4400 25%、冰1 15%）
   ├─ G402  条件检测（烟雾、钩爪 7F(-999)、目标状态 0/14/11、泥浆、飞行…）
   ├─ G115  转阶段/大招计数：冰0 R0 / 冰1 R1 / 冰2 R2
   ├─ 飞行 → node_011 空中吐息落地
   ├─ G143  远距离冲刺（R7=1）
   ├─ node_006 主攻击表：随从猫 010 / 冰2 009 / 冰1 008 / 冰0 007
```

| 寄存器 | 含义 | 规则 |

## 4. 关键结论

1. **半血以下：冰2 王冰每次都会连出两轮。** 压起身计数 `node_005` 的条件是 `function#10E(3,50)` 或目标受击硬直。exe 确认 `10E(3,50)` = **目标 HP ≤ 50%**（不是社区以为的「被击飞」）。满足时冰2 **100%**、冰1 50% 置 R8，`node_004` 末尾 repeat，不换目标立刻再走一轮攻击，这一轮照样累计转阶段/大招计数。
2. **冰2 的六脉只在地区中心。** 冰2 在中心 1200 内每轮约 30%~40% 出六脉；在板边为 0，改为推推冰 20%~33%、横扫冰 27%~36%。冰1 任何位置都不出六脉。
3. **「地区中心」是一个圆。** `10F(d)` = 冰呪龙到区域中心点的水平距离 < d。半径写在 THK 里：龙结晶之地 区域 1/5/7 为 1500、2/6 为 1250、4 为 1750、8 为 1825，其他地图 1500。判断的是冰呪龙出招前自己的位置。
4. **车 / 后撤尾刺总是往中心走。** `G016`、`G129`：离中心 <750 时 50/50；否则目标与中心同侧就车向目标，相反一侧就后撤尾刺，其余 50/50。
5. **R9 两条序列互不干扰**：尾刺派生（`G042/043`）与前置招（`G044/045`）各占一位，分别翻转。
6. **转阶段与大招看给招次数**（见第 3 节）；历战王冰0 在 **HP≤40%** 转阶段时直接冰甲全开（冰2），否则先升冰1（`G280`）。
7. **冰1 每 5 轮必有一次额外横扫冰**；目标半血以下或倒地时，未满 5 的轮次每轮还有 25%（`G126`）。冰2 的同一分支权重全为 0。
8. **粘鼠板 / 大招后的落冰**：招式后紧接 `G142` 落冰；若被打断，下一轮开头 `G141` 看到 R7=2 补上落冰。
9. **远距离先冲刺**：1300~3300 冰0 75%、冰1 按 R3 25/50/100%、冰2 固定 25%（R3 每轮清零）；3300 外必冲刺。冲刺后直线吐息（`G033`）、横扫冰（`G034`）在 1300 / 1600 内改走近战分支 `G035`。
10. **随从猫是另一套表**：`self.target(44)` 检查目标标志 bit14，exe 确认这一位属于随从猫（uOtomo）。对随从猫时用 `node_010`，不出额外横扫冰/压起身横扫冰；`G178` 只在这里有 10%。
11. **死代码**：`G009`、`G012` 的 `return` 之后各残留两段执行不到的代码；`G126` 冰2 分支、`node_008/009` 的 `G178` 权重均为 0。

## 7. exe 逆向

方法同黑龙：游戏运行时只读导出内存镜像、Capstone 反汇编；本次把「类名 → DTI → newInstance → 构造函数 → 虚表 → `+0x8d8` 专属条件处理」写成了脚本，对金狮子复现了之前手动找到的结果。地址只适用于 build 421810。

| 步骤 | 地址 | 内容 |
|---|---|---|
| `uEm124` 构造 | `0x140a48e30` | newInstance `0x140a48c00` 以内部编号 0x4F（79 = 冰呪龙）调用；虚表 `0x1430935c0` |
| 专属条件处理 | `0x140a49a80`（虚表 `+0x8d8`） | `switch (functionType - 0x101)`，0x101~0x111 共 17 个 case |
| 区域中心点 | `0x140a4eaf0` | 用怪物位置与所在区域编号（`+0x1228c`）查询场景数据 |

| 函数 | exe 中的逻辑 | 结论 |
|---|---|---|
| `101(p)` | p≤2：冰甲对象（`+0x20928`）等级 == p；p=4：等级 ≥ 1 | 冰0/冰1/冰2；`101(4)` 身上有冰甲 |
| `10E(op,v)` | 取目标血量比例 ×100（猎人 `+0x7630`、怪物 `+0x7670`、随从猫 `+0x7f58` 的血量组件，当前值 / 最大值），通用比较 `0x141338ee0`：op 0 ==、1 ≥、2 >、3 ≤、4 <、5 ≠ | `10E(3,50)` = 目标 HP ≤ 50% |
| `10F(d)` | 区域中心点与怪物的水平距离² < d² | 冰呪龙离地区中心 < d |
| `110(a,b)` | 区域中心点相对怪物朝向的角度在 a~b | 中心方位 |
| `111()` | 取区域中心点并设为 AI 目标位置，返回真 | 横扫冰前「车向中心」 |
| `104()` | 一次性事件标志 `+0x20a48`，读后清零 | |

通用函数（所有怪物共用）：

| 函数 | exe 中的逻辑 | 结论 |
|---|---|---|
| `self.target(N)` | 函数 0x2E「目标状态 N」（`0x141338000`）：0x2C 检查目标标志 bit14；0x37 读猎人 `+0x7668` 子对象并与本怪物比较；0/14 读猎人状态位 `+0x8944` | target(44) = 目标是随从猫；target(55) 与 xlsx「钩爪挂身」一致 |
| `2D(p)` | 目标标志位 p=0 bit0 / p=1 bit14 / p=2 bit1 | **bit14 只出现在 uOtomo（随从猫）对象**：其血量组件在 `+0x7f58`，由 uOtomo 构造函数 `0x142006bb0` 写入。所以金狮子、黑龙里的 `2D(1)` 都是「目标是随从猫」 |
| `7D()` | 怪物自身血量比例与一个区分单人/多人的阈值比较 | 推测为「血量低于捕获线」，转阶段时直接冰2 |
