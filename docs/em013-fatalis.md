# 黑龙 Fatalis（em013_00）AI 解析

> 交互版（出招模拟器、扇区热力图、带中文注释的 THK 代码）：<https://mhwi.helsincy.com>（或本地打开 `web/index.html`）。
> 本文所有概率都由 `scripts/sim.js` 对 THK 全部随机分支做**精确枚举**得出，可用下文命令复现。

## 1. 数据来源与方法

| 步骤 | 工具 | 说明 |
|---|---|---|
| 解包 | `tools/mhw_chunk.py` | 移植自 MHWNoChunk 的命令行版：Oodle 解压 + 16 字节 XOR 解密，合并 chunkG0~G60 |
| 反编译 | `tools/decompile.py` → Leviathon | `em013.thklst` + 18 个 `.thk` → `data/em013_00/*.nack` |
| 结构化 | `tools/nack2json.py` | nack → JSON AST；`scripts/check.js` 逐行往返校验（5550 段 / 587 个 if / 670 个随机块全部一致，随机权重和均为 100） |
| 求值 | `web/js/thk-core.js` | 按 Leviathon 规范的执行语义解释 THK，对随机分支深度优先全枚举，得到精确概率 |

**关于「官方招式名」**：游戏文本（`em_info_chS.gmd` 猎人笔记等）只有怪物简介与攻略提示，**没有面向玩家的招式名**。唯一的官方命名是写在 `MonsterHunterWorld.exe` 里的内部动作名（例如 `L2_SPECIAL_WIDE_RANGE_FIRE_SHOOT` = 扇形火），本文和网页都同时给出内部名、逐词直译和社区俗称。

## 2. AI 文件结构

`em013.thklst` 有 72 个槽位，实际使用 14 个 THK：

| 上下文 | 文件 | 作用 |
|---|---|---|
| Combat_Main | em013_00 | **战斗主控**，193 个节点 |
| Global | em013_55 | **招式库**，143 个节点，被所有上下文调用 |
| Combat_Enter | em013_01 | 进入战斗（任务 51612 有专属开场招） |
| Mount | em013_11 | 骑乘 |
| Non_Combat_Main / Non_Combat_Hit / Target_Lost / … | 其余 | 非战斗、丢失目标等 |

一轮决策从 `em013_00.node_000` 开始，选出一招后 `reset` 回到入口重新判定：

```
node_000
 ├─ G142  清零骑乘计数 R12
 ├─ 001   丢失目标 / 烟雾弹 (5D)
 ├─ 027   10A 特殊攻击（三阶段，实战未出现）
 ├─ 014   一二阶段血量：HP≤77% 1转2，HP≤49% 2转3
 ├─ 017   三阶段血量：HP≤40/25/5% 各一次终极大招
 ├─ 002   起飞/降落计数（双翼破坏则不飞）
 ├─ 035   一阶段瓦砾
 ├─ target(3/4) → 006；target(55) 钩爪 → G004 反钩爪
 ├─ flying → 008 飞行攻击 AI
 └─ else   → 009 地面攻击 AI
            高台(041/051) → 112(022) → 110(2)(018) → 转姿态计数(010)
            → 一阶段额外车(015) → 目标是随从猫 2D(1)(157) → 5% 捕食(016) → 遮挡(038) → 对空(019)
            → 主攻击表：姿态 × 阶段 × 距离（063~108）
            → 109 受击追加
```

**连段的本质**：地毯→扇火、大拍→扇火、受击追加等都发生在攻击节点内部，所以连段之间**不会**重新做烟雾、血量、钩爪、高台检测。

## 4. 关键结论

1. **距离决定查哪张表，角度只挪动表内权重。** 侧面的侧面地毯、背后的甩尾只占 20~30%，任何角度都可能出正面招。
2. **扇火的三个来源**：主表直接扇火（一阶段头前 20%）；正面地毯**必接**扇火、大拍/吐痰/孕吐 **35%** 接扇火（都需要目标在前方 180° 且距离 >800）；受击追加表。开局 `10E()` 期间（发现目标后前 5 次 AI 出招，见第 7 节）所有扇火节点改为随机出单火球/三连/地毯/直线火。
3. **一阶段转四足是 10%**（xlsx 正确，B 站正文写的 15% 与代码不符）。
4. **一阶段从不吐痰**（主表里吐痰权重全为 0），二阶段起吐痰最高 50%。
5. **一阶段四足贴脸（≤500）正面/背后有 10% 只后退不攻击**，这一轮以后退结束。
6. **三阶段二足的 5% 捕食判定排在主表之前**，因此三阶段二足所有招式概率都是二阶段同表的 0.95 倍。
7. **受击追加 50% 在三个阶段都生效**（判断排在阶段判断之前）；二阶段/三阶段另有 `113(3,40)` 时 30%/50%。
8. **高台横扫火「7 招必出」是死代码**。
9. **任务 51612「黑龙」（讨伐黑龙·5 次力尽，任务名取自解包的 `q51612_chS.gmd`）有专属开场招 G139** 与一阶段专属姿态计数节点 `00.node_011`。
10. **遮挡 `10D()`**：二足 900~6000 / 四足 1500~6000 时进入遮挡 AI，大概率出车。

## 7. exe 逆向：开局不扇火（`function#10E()`）

社区说法是「开局约 15~20 秒不扇火」（B站九世深渊实测为小地图变红后约 20 秒）。THK 里只能看到这是由 `function#10E()` 控制的，`0x100` 以上的函数是怪物专属的，实现在游戏 exe 里。下面是逆向结果。

### 结论

`function#10E()` **不是计时器**，而是：

```
10E() = 调参表阈值(5) > 开局计数
```

- **阈值 = 5**：写在黑龙专属调参表 `em013.dtt_unq`（类 `nEmDtTune::cEmUniqueEm013`，对象偏移 `+0x17c`），代码默认值是 3，文件覆盖为 5。可用 `python tools/em013_unq.py` 查看。
- **开局计数**（`uEm013` 对象 `+0x20c5c`）：
  - 黑龙**每切换到一个新动作**时 +1，上限 100。
  - **不计数**：新动作在调参表的「不计数列表」里（只有一项：`L2_BIND_VOICE` 二足咆哮）；或者这次切换是**当前动作自己衔接的后续段**（例如车的起手→冲刺→收招、受击硬直等由动作代码直接切换的情况）。THK 选择的动作（包括转身、后退、步行）都会计数。
  - **清零**：怪物发现目标、进入战斗时（`nEmAI::CombatFindBehavior` / `LeadFindBehavior` 开始时）。**例外**：如果此时有猎人与黑龙在同一区域，且仍在黑龙的仇恨列表中（列表项已登记、仇恨值曾达到阈值），就不清零。
- 所以「开局保护」= **发现目标后前 5 次 AI 出招**（咆哮不算）。期间扇火类节点（`G064/068/079/081/088`）都改为随机出单火球/三连/正面地毯/直线火。黑龙一招大约 3 秒，5 招正好对应社区观察到的 15~20 秒。
- 实战推论：转身、后退会消耗计数；**丢烟雾弹后重新索敌不会清零**（猎人一直在同区域、仍在仇恨列表里）；**用回归球离开区域、回来后再被发现会清零**，重新获得 5 次开局保护。这两点与九世深渊的实测一致（[B站 opus/930951641929089095](https://www.bilibili.com/opus/930951641929089095)）。该文从实测得出「开局约 20 秒」，但同文「不拍怒等 5~6 招后开始扇火」的观察正好对应阈值 5。
